# Test Run 3 — the loop

A full-catalogue regression run — **124 pages, 1,295 cases** — where defects are
**fixed during the run** rather than collected for a later pass.

The per-batch procedure lives in `tester/skills/run-tests/SKILL.md`. This file is
the **cycle** around it: what happens between batches, and what must never
happen.

---

## 🛑 A status summary is not a turn boundary

This is the single most important line in the file.

The failure it prevents is specific and has already cost a session: writing a
progress report and treating it as the end of the turn, which forced the user to
type "continue", "why stop?" and "who said to stop?" repeatedly. A note about it
was written and the behaviour recurred anyway — **a note is not a mechanism**.

So:

- **A turn ends with a tool call that advances disk state**, or it does not end.
- The Stop hook (`scripts/claude-hooks/tester-loop-continue.mjs`) blocks the turn
  and hands back the exact next command. It is not a reminder to continue; it is
  the command.
- Reporting progress is something you do **on the way past**, never instead of
  the next action.
- Running out of things to say is not running out of things to do. Check
  `node scripts/test-run-status.mjs` and act on what it says.

**Off switch, for the human:** set `active: false` in
`tester/.tester-runs/loop-state.json`, or delete it. One step, no code edit.

---

## First action of every turn

```bash
node scripts/test-run-inflight.mjs --check
```

Non-zero means the previous turn died mid-batch — fixtures seeded, an identity
copied over `session.json`, some cases tested, no memory of any of it.

**Recover by tearing down and restarting that batch from case 1. Never resume
it.** Resuming assumes the fixtures are in the state the next case expects, and
nothing on disk can establish that — the browser did work Firestore does not
record. A restart costs one batch; a wrong resume costs a verdict that looks
exactly like a good one.

## Phase 1 — audit (current phase)

No verdicts are produced. The catalogue is made to match the code as it is today.

The ledger is `docs/TEST-RUN-3-AUDIT.md`, regenerated by
`scripts/test-run-build-audit-ledger.mjs`, which scrapes the seed. **Never
hand-add a page row** — add the page to the seed and regenerate, or the ledger
claims coverage the catalogue does not have.

Per page:

1. Mark it `in-flight` in the ledger.
2. Read the overlay (`appkit/src/features/tester/seed-data/authored/<group>__<page>.ts`)
   and its catalogue entries.
3. Read **the actual source** — the route under `src/app/[locale]/**`, its view
   component, its API route. Not the old docs. Not this repo's own description of
   the feature, which is frequently out of date and is why the audit exists.
4. Check each case's six parts against what the code does:
   - `startPage` resolves to a real `page.tsx`
   - `steps` name controls that still exist, in the order they appear
   - `inputs` are literal, and cited fixture ids are still seeded
   - `expectedBehaviour` / `expectedUiState` quote text the code actually renders
   - `expectedData` keys are readable off the screen
   - `endResult` names what survives a reload
5. Rewrite what drifted, in place. Delete cases whose feature is gone.
6. `npm run check` green, then mark `audited` or `rewritten` with a one-line note.

**A product defect noticed during the audit goes to
`docs/TEST-RUN-3-OUTOFSCOPE.md` and is NOT fixed.** Phase 1 changes cases, not
features.

## Phase 2 — the run

### Preflight, once per cycle

```bash
node scripts/test-run-preflight.mjs
```

Six checks, any of which refuses: production health (with a nonsense control),
nothing in flight, session files sane, **plugin cache matching the repo**, read
budget under half the daily quota, `npm run check` green.

The plugin-cache check is not bureaucracy. Installing *copies* the plugin into
`~/.claude/plugins/cache/`, and **the cache wins over `--plugin-dir`** — a run
started minutes after a fix has already executed the old code and written verdict
files with no labels, reproducing the just-fixed bug at full speed with nothing
erroring.

### Per batch (×5)

```bash
node tester/scripts/next-batch.mjs --run run-3
node tester/scripts/fetch-cases.mjs --run run-3 --page <key> --out <f>
node scripts/test-run-inflight.mjs --start <key> --identity <role> [--fixtures]
node tester/scripts/seed-batch-fixtures.mjs --batch <key>        # if [has fixtures]
# copy tester/.tester-runs/session-<role>.json -> session.json, then browser_close()
#   -> the MCP reads --storage-state when the CONTEXT is created, so copying over
#      an open browser changes nothing
# ... drive the browser, per tester/skills/run-tests/SKILL.md ...
node tester/scripts/record-verdicts.mjs --run run-3 --batch <f> --verdicts <v>
node tester/scripts/seed-batch-fixtures.mjs --batch <key> --teardown
node scripts/test-run-inflight.mjs --done
```

### Fixing — the rules that keep the run from wandering

**Fix every defect before advancing.** Then:

1. **Re-verify against live production first.** A route that 404s in a report
   usually exists in source (CLAUDE.md Rule #4).
2. **Fix at the root.** If the bug has copies — the recurring shape here — fix
   all of them in the same cycle.
3. **`npm run check` green** before the cycle closes.
4. **Re-drive the failing case.** A fix nobody re-tested is a hypothesis.
5. **Record it**: append to `tester/.tester-runs/run-3/fixes.jsonl` as
   `{"caseId","batchKey","summary","files":[],"reVerified":true,"at":"…"}`.

**G4 — a fix must name the case that found it.** Anything noticed that no case
found goes to `docs/TEST-RUN-3-OUTOFSCOPE.md`, one line with evidence, **not
chased**. This is the main way a long run stops producing coverage.

**G5 — a defect gets 6 turns.** If it is still unfixed, write it to
`state.fixQueue` in `loop-state.json` with its evidence, record the case as
`❌ fail / deferred-to-milestone`, and **advance**. The milestone drains the
queue, where a schema change or Function redeploy is legal anyway. The escape is
automatic so it does not depend on noticing you are stuck.

**G6 — re-drive a contradiction before recording it.** Any `no` whose claim is
"this whole page is empty/missing", or that contradicts an earlier `yes` on the
same surface, is re-driven from a fresh navigation first. A previous run recorded
that two brand pages rendered empty; direct navigation later showed 20 and 8
products. A retraction is a **new row** marked `retracted`, never a silent edit.

### Every 5 batches

Append the rows to `docs/TEST-RUN-3.md`, then:

```bash
node scripts/test-run-status.mjs
```

**Never type a count into the document.** The counter block is rewritten from the
verdict files. A hand-kept tally once reported 17 failures where the files held
15 — it had been counting calibration controls, and nothing could catch it,
because the only other copy of the number was the prose.

### Every 25 batches

```bash
node scripts/test-run-milestone.mjs
```

Autonomous, by standing authorisation from the user for this run only — it
overrides CLAUDE.md Rule #10, and covers nothing beyond these milestones.

## Verdicts

`yes` / `no` / `null`. **`null` — "could not test" — is first class** and always
better than a guess: a fabricated `yes` is a false green on a case a human would
otherwise have run, and nobody will ever look at it again.

Every answered verdict needs a screenshot that exists on disk, **including
passes**; `record-verdicts.mjs` enforces it. A pass with no image is
unfalsifiable, and is exactly where a fabricated one hides.

Every `no` needs evidence: quoted screen text, an HTTP status and URL, or a
console error. Then find the cause and report both — symptom first, cause second.

## Never

- **Never call `/api/auth/login|session|me`** from the browser or a script. One
  10-request-per-minute bucket keyed on IP; `fetch-cases.mjs` is the only caller.
- **Never modify a user account, login, saved address, or Site Settings.** Those
  are PRESERVE-tier and survive the run by design — damage there is the only
  permanent damage available. The catalogue is wiped and reseeded, so mutating
  listings, carts and orders is fine.
- **Never spawn a Claude session.** `run.mjs`, `pool.mjs` and `sweep.mjs` were
  deleted for producing ~300 sessions in a day. Batches are worked here, in this
  session, one at a time.
- **Never substitute an API call for a UI action.** The network panel is for
  explaining a failure already seen on screen. Nearly every bug here returns 200.
