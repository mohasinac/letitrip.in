## How a class reaches a browser

The single fact that explains every delivery bug in this repo:

> `src/app/globals.css` carries **`@source not "../../appkit"`**, so the
> consumer's Tailwind build never scans `appkit/src`. **Every class authored
> inside appkit must be generated by appkit's own build, or it reaches
> nobody.**


| Stylesheet | Carries | Built from |
|---|---|---|
| `appkit/dist/tailwind-utilities.css` | Tailwind utilities | `appkit/tailwind.config.js` + `appkit/src/tailwind-input.css`, scanning `appkit/src` |
| `appkit/dist/styles.css` | hand-written `appkit-*` BEM | `appkit/src/**/*.style.css`, flattened by `bundle-css.mjs` |
| `src/styles/globals.compiled.css` | the app's own Tailwind + utilities | `src/app/globals.css`, scanning `src` only |

A class in `appkit/src` that appkit's config cannot generate is dead in
**both** directions — appkit never emits it, and the consumer never looks.
That is why the status colours had to be added to `appkit/tailwind.config.js`
(2026-08-21) and why `fluid-grid-card` reached no other consumer at all.
