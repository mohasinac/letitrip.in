## What this run is for, and how to read a ❌

**A `no` here does not mean a defect.** Run 4 forbids `null`, so a case that
cannot be answered is recorded as `no` with the reason. In practice the ❌ rows
fall into four groups, and the comment on each says which:

| Shape | Meaning |
|---|---|
| **Reproduced defect** | genuinely broken, root-caused, queued in `fixes.jsonl` |
| **Not driven** | ran out of session capacity; the comment says what to do next |
| **Blocked** | needs a session, a mailbox or a fixture the harness does not have |
| **Case is wrong** | the product is right and the case's expectation is not |

That last group is real and worth watching for — `redirect-only-page-no-canonical`
expects a canonical the documented tab-family rule forbids, and honouring it
would contradict a sibling case that passes in the same batch.

**The run-3 position this is measured against:** 1,337 of 1,847 cases recorded —
465 pass / 203 fail / 669 null. Two corrections from re-driving changed what that
backlog *is*: on the core happy-path slice **6 of 7 failures were already fixed
and never re-driven**, and only 12% of the 203 carry prediction language. The
rest are discoveries or stale.
